# Power BI build guide

## Data connection options

### Preferred: PostgreSQL views

Connect Power BI Desktop to database `olist_portfolio` and import the seven `analytics.dashboard_*` views created by `sql/17_create_dashboard_exports.sql`. Use local PostgreSQL credentials and never place them in a project file or screenshot.

### Portable fallback: curated CSV extracts

Import the seven files under `dashboard/data/`. They are small aggregate analysis outputs generated by `sql/19_export_dashboard_csvs.sql`; they are not raw Olist data.

## Power Query names

Rename imported tables to:

- `Executive KPI`
- `Monthly Trend`
- `Category State`
- `Seller`
- `Route`
- `Delay Band`
- `Growth Contributor`

Set data types explicitly:

- IDs and labels: text;
- counts/ranks/sort fields: whole number;
- GMV/freight/AOV/duration: decimal number;
- rates/shares/growth: decimal number formatted as percentage;
- `purchase_month`: date;
- Boolean rule flags: true/false.

## Relationships

Create **no relationships** among the seven aggregate tables. Each has a different declared grain. A relationship would either be meaningless or create ambiguous filtering/fanout.

Sort:

- `Executive KPI[period_label]` by `period_sort`;
- `Delay Band[delay_band_label]` by `band_order`;
- action posture labels by `action_sort` where available;
- `Growth Contributor[dimension_value]` by `growth_rank` only within a filtered `dimension_type` visual.

## Measures

Create the measures from `MEASURES.dax`. Use ratio measures built from summed numerators and denominators; never average row-level rates for totals.

## Pages

Build the three pages exactly as specified in `docs/DASHBOARD_SPEC.md`:

1. Executive overview
2. Opportunity portfolio
3. Fulfillment & CX

Recommended canvas: 16:9. Keep filters in a consistent left or top band and reserve the main area for decision visuals.
